## Project objective

Take a user's prompt, decompose it into intent elements with an LLM, ground it using ontology concepts and business rules, and assess relevant elements against actual Etiq execution evidence. There are three categories: intent, ontology and business rules; provenance is metadata. Examine whole-pipeline input/output and selected intermediate function inputs/outputs. A state is a captured object produced by an operation, not a named business stage. Outputs remain ordinary workflow values; no embedded intent/rule objects are required.

Etiq already captures the pipeline. Our work exports, indexes and packages its native evidence for bounded review. Preserve native data/function/data edges and supported nesting. Runtime sidecars supplement capture and cannot substitute a fabricated native graph. Keep absent capture and summary limitations explicit.

### Full primary matrix

Every arm receives the original user prompt, identical three-category inventory and whole-pipeline input AND output statistics/descriptions. None receives the hidden catalogue, injection truth, sibling answers, full repository or full producer source.

| Arm | Whole-job input/output | Top-level function input/output | Graph description at visible nesting | Open internal functions/inspect newly visible artifacts | Model review calls |
| :--- | :---: | :---: | :---: | :---: | :--- |
| E: endpoints | Yes | No | No | No | 1 |
| R-H: repeated endpoint control | Yes | No | No | No | Same actual count as paired H |
| H: fixed high-level review | Yes | Yes, predeclared batches | Yes, top level only | No | K_H, fixed after batching qualification |
| R-A: repeated endpoint control | Yes | No | No | No | Same actual count as paired A |
| A: adaptive nested review | Yes | Yes, same starting view as H | Yes, currently disclosed levels only | Yes, bounded selected openings | K_A, all review/selection/follow-up calls counted |

Use the same model/settings and final assessment schema. Freeze H batch count and A maximum logical calls in the dry-run protocol; actual A count may stop early. The controls match actual logical calls per case/repeat, including charged reasoning retries; transport failures are recorded separately and handled by a frozen policy. If K_H=1, R-H is equivalent to E and provides no distinct extra-call contrast. Never manufacture extra H calls to justify a control. Adaptive selection is part of the counted review call, not an untracked selector model.

Reference-style opening/inspection may require further review calls: each such call has a matching same-evidence control reconsideration. Controller operation counts and added evidence bytes are separate. Hash endpoint-control evidence before/after every reconsideration. Match only the neutral count; controls cannot see treatment reasons/results. Each invocation is fresh; controller replays only its own arm's approved evidence, with any own-answer history policy explicitly frozen and consistent. Hidden payload files are not mounted even if their descriptors are visible.

Primary comparison is endpoint-only versus checking intermediate function outputs as well. Repeated-call controls test whether gains reflect extra model calls.
